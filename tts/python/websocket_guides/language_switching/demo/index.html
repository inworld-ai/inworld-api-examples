Language switching on one TTS context

A tutor turn marks the language being taught with <l2>…</l2> and spells it so that its sounds are certain: kana for Japanese, pinyin for Chinese, IPA for Spanish words. One WebSocket client (language_switching.py) sends it two ways, as one flush or as one flush per language, and each card below is one of those on one voice.

What decides what you hear

The spelling decides the sounds

The voice speaks what the spelling says, whatever language it is in. Kanji and Chinese characters have several readings each, and the same characters read differently in Chinese and Japanese; a Spanish word can be read as English. Kana, pinyin with tone marks, and IPA have one reading. Ask your LLM to write the taught language in them.

Detection picks one language per flush

The context sets no language, so the service detects one for every flush, by its script first:

  • Kana reads as Japanese; Hangul as Korean.
  • Chinese characters read as Chinese or Japanese; a word or two can go either way, or neither.
  • Latin letters go to a model, which needs a few words: a single Spanish word can read as English.
  • Pinyin never reads as Chinese: hǎochī reads as German.
  • IPA reads as no language, so the flush takes the language of the turn so far.

The prompt decides the accent

A voice with localized prompts speaks each flush on its prompt for the detected language, when per-language prompt switching is enabled for your workspace; otherwise every flush uses its own prompt. A voice cloned from a clip in both languages has one prompt with both accents, so no detection is needed for its accent.

The detected language also sets how numbers are read, and timestamps.
